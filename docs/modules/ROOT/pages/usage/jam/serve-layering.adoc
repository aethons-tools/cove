= Layering serve configs
:summary: `jam serve --config` repeated — how several serve-config files merge, the host keys the first (repo-owned) file may not set, and how `config diff` compares the repo's `jam.yml` with the running config.
:read_when: You run `jam serve` with more than one `--config`, serve or `config diff` refused with "… is a host key; put it in jam.local.yml", or a `config diff` of `jam.yml` says `differs (restart to apply)`.
:owns: the layered `--config` overlay, the host-key table, and the `jam.yml` diff states
:prereqs: serve.adoc for the serve-config keys; config-git.adoc for the config repo layout
:tier: leaf
:updated: 2026-11-13

`+--config+` is repeatable: `+jam serve --config jam.yml --config jam.local.yml+`.
Files merge in order — maps merge by key, scalars and lists replace — so a
later file overrides an earlier one. One `+--config+` behaves as before.

The first file is the portable, repo-owned one (a Jam's `jam.yml`); per-host settings belong in a later file. With
two or more `+--config+` files, the first may not set a *host key*; serve
refuses to start (and `config diff` refuses) with
`+jam.yml: listen is a host key; put it in jam.local.yml+`.

[%header]
|===
|Host key |Why it is per-host

|`listen`, `admin-listen` |bind addresses
|`ui-hosts`, `ui-origins` |host names the UI is reached by
|`dev-identity` |local-only sign-in
|`tls`, `admin-tls`, `previews.tls`, `destinations.tls` |certificate files on this host
|`store-postgres` |this host's database
|`state-dir`, `credentials-file`, `pool.store` |paths on this host
|`config` |the repo it names can't also carry it
|===

The config diff compares the repo's `jam.yml` with the running serve's merged
config minus host keys: `same`, `differs (restart to apply)` with dotted key
paths, `absent` (no `jam.yml`) or `unknown` (no running serve config).
The `config` verbs and the repo layout are in xref:usage/jam/config-git.adoc[config-git].
