= Studio Manager live test
:summary: The manual live-test checklist for remote Studio Managers — a containerized Jam plus a bare-metal `jam-colima` on a Mac, covering raise, teardown, pause, a kit build, a draft build, a Jam restart and a manager restart. It gated removing the in-process launcher (done in plan 6).
:read_when: You are running the Studio Manager live test (a Jam container plus a manager on a Mac), validating a new manager build or host, or reproducing a manager problem end to end.
:owns: the Studio Manager live-test procedure, its expected results, and the gate it set for deleting the in-process launcher (done in plan 6)
:prereqs: container.md (running Jam in a container); ../jam-colima.md (the manager's config); studio-managers.adoc (Jam's side)
:tier: leaf
:updated: 2026-11-05

This is the one manual run that proves remote Studio Managers work end to end.
It uses a Jam in its container and a bare-metal `jam-colima` on a Mac with Colima.
Do the items in order. Each one gives the command and the result to expect.
This run gated the removal of the in-process launcher (done in plan 6); the runbook stays for validating new managers.

== Setup

* A Mac with Colima running, and the repo checked out.
* A trusted cert for `jam.local.aethons.tools` in the secrets directory's `tls/`, and the OIDC tenant from the container config (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/container.md#running-it-with-the-dev-compose[container.md]).
* Jam and the manager on one version (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/container.md#version-lockstep[lockstep]): `just build && just jam-image` from one checkout, or a release image with that release's `jam-colima`.
* The `anthropic` and `git` destinations need credentials in the container: uncomment the `anthropic-key` and `git-pat` placeholders in `dev/jam.container.yml` and the secrets directory's `credentials.yml`, fill in real values, and restart Jam (`just dev-jam-up`).
* After step 2, a project and a role that grant the `anthropic` and `git` destinations (xref:usage/jam/roster.adoc[], https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/coves.md#raising-a-real-managed-studio[coves.md]), and a kit for the role (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/kits.md[kits.md]), committed to the config repo the Jam follows (a local one: https://github.com/aethons-tools/cove/blob/main/dev/README.md#config-a-local-repo[dev/README.md]).
* `jam` on the Mac, signed in: `+jam login --admin-url https://jam.local.aethons.tools:8081+` (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/container.md#admin-access[admin access]).

The examples use the manager name `mac-1`, the role `acme/guest` and the kit `app`.

== The checklist

. *Jam comes up in its container.*
`just dev-jam-up`, then `just dev-jam-logs`.
Expect: serve starts and logs `+Jam studio managers: accepting connections+` with `registered=0`, and no launcher line. `docker compose -f dev/docker-compose.yml ps` shows `jam` running.
`just dev-jam manager list` prints nothing and exits 0.
. *The host CLI reaches the admin API over OIDC.*
`jam whoami`, then `jam manager list`.
Expect: your operator identity, and the same empty list.
The published `+127.0.0.1:8081+` is not treated as loopback, so a request with no token is refused.
. *Register the manager.*
`jam manager add mac-1`.
Expect: `+manager mac-1 token (shown once): <token>+`. Save the token in the manager's `token-file`.
. *Run the manager.*
Write `+~/.config/jam-colima/config.yml+` with `+name: mac-1+`, `jam-addr` and `colima.runtime-addr` set to `+jam.local.aethons.tools:443+`, and `colima.jam-host` set to `jam.local.aethons.tools` (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/container.md#pointing-studio-managers-at-it[pointing managers at it]). Then run `jam-colima run`.
Expect: it connects with no refusal. `jam manager list` shows `+mac-1	connected=true	version=<Jam's>	studios=0	…	strays=0+`.
. *Raise a studio on the manager.*
`+jam studio raise --id live-1 --role guest --project acme --manager mac-1 --prompt-file task.md+`.
Expect: `studio list` shows `live-1` going `raising` → `live` with `manager=mac-1`.
On the Mac, `+docker ps --filter label=jam.studio.manager=mac-1+` shows `jam-studio.mac-1.<id>`.
The agent reaches Anthropic and git through Jam (activity `running`, then `waiting`).
. *A kit build on the manager.*
Change a build-affecting field of the role's kit (`kits/app/` in the config repo), commit it and wait for Jam to apply it (`jam config status`), then raise `live-2` as in item 5.
Expect: the manager builds the new image, and the raise waits for it, then goes `live`.
`jam role images acme/guest` shows a `mac-1` row with the new tag.
. *Pause and unpause.* There is no pause verb: Jam pauses through the idle ladder (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/intercom.md#waiting-for-a-reply-wake-on[wake-on]).
Leave `live-1` `waiting` past `runtime.wake.warm-timeout` (default 60s).
Expect: `studio list` shows phase `idled`, and `docker ps` shows the container `(Paused)`.
Then send the session a message in the Inbox (`/app/user`).
Expect: Jam unpauses it, it reconnects, and it is woken: phase `live`, activity `running`.
. *A draft build on the manager.* Retired: live kit drafts and their test builds were removed (https://github.com/aethons-tools/cove/blob/main/docs/usage/jam/kits-drafts.md[kits-drafts.md]). The recorded run passed it; a new run skips it.
. *Jam restarts and the manager reconnects.*
`docker compose -f dev/docker-compose.yml restart jam`.
Expect: the studios on the Mac keep running throughout. While the manager is reconnecting (its backoff is at most 30s), Probe answers Unknown, so nothing is reaped (xref:usage/jam/studio-managers.adoc#disconnect[disconnect]).
Afterwards, `manager list` shows `mac-1 connected=true` with the same `studios=` count and `strays=0`, and `studio list` shows the same studios still `live`.
. *The manager restarts and leaves its studios running.*
Stop `jam-colima run` (Ctrl-C).
Expect: `docker ps` still shows its studios, and `manager list` shows `connected=false` within 30s.
Run it again.
Expect: `connected=true`, the same `studios=` count, `strays=0`, and no studio marked lost (xref:usage/jam/studio-managers.adoc#reconnect[reconnect]).
. *Teardown.*
`+jam studio teardown --id live-1+`, and the same for `live-2`.
Expect: each goes `terminating` → `gone`. Jam logs the `cove agent log (tail, captured on teardown)` line, and the containers are gone from `docker ps -a`.
. *Final state.*
`jam manager list`.
Expect: `+mac-1	connected=true	…	studios=0	…	strays=0+`.
. *The result.* All of items 1 to 12 passed against the containerized Jam.
This run gated the removal of the in-process launcher (done in plan 6).
For a new manager, record the version tested and anything that needed a workaround.

Clean up with `just dev-down` (or `just dev-down -v` to wipe the volumes) and `jam manager revoke mac-1`.
