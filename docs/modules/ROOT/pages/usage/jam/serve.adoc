= Running Jam (`jam serve`)
:summary: Running the Jam service — `jam serve`, the serve-config YAML and its key table (listen, admin-listen, tls/admin-tls, store-postgres, state-dir, credentials, the subscription account pool), the credential-broker model, and the off-loopback fail-closed rule; the store, upgrades, layering and destinations have their own pages.
:read_when: You are standing up or configuring a Jam service — writing its serve config, wiring the real credentials it brokers, enabling the subscription-OAuth account pool, or exposing the admin API beyond loopback.
:owns: the `jam serve` command + serve-config key table (listen/admin-listen/tls/admin-tls/store-postgres/state-dir/credentials/pool/ssh/config/kits/blobs/previews/destinations), the broker model, and the off-loopback exposure guard (the store and ledger are serve-store.adoc's, upgrade notes serve-upgrades.adoc's, the `--config` overlay serve-layering.adoc's, destinations destinations.adoc's)
:prereqs: INDEX.adoc for the service overview; operators.adoc for the `operator-auth.oidc` block referenced here
:tier: leaf
:updated: 2026-11-13

`+jam serve --config <file>+` runs one process that is both the *broker*
(the reverse proxy studios send Anthropic/git through) and a *loopback admin API*
(the control plane the `jam` admin verbs talk to). Both are backed by a
single *Postgres* store (`store-postgres`, required). The serve config is bootstrap-only: destinations,
roles, kits and the rest of the configuration live in the config repo the Jam
follows (xref:usage/jam/config-git.adoc[config-git]); enrollments and grants are made at
runtime via the admin API.

----
jam serve --config /etc/jam/jam.yml
----

[#the-serve-config]
== The serve config

[source,yaml]
----
display-name: Aethon           # optional; the admin UI's title bar reads "Aethon Jam"
listen: ":443"                 # broker listener (coves connect here; TLS in prod)
admin-listen: "127.0.0.1:8081" # admin API listener (operator surface)
ui-hosts:                      # optional; extra Host values the browser UI accepts on loopback
  - jam.local.example       # a custom name that DNS-binds to 127.0.0.1
ui-origins:                    # optional; extra origins the UI's write (CSRF) check accepts
  - http://localhost:8090      # e.g. a proxy fronting the admin listener
tls:                           # broker server cert (required for a real :443)
  cert: /etc/jam/tls/fullchain.pem
  key:  /etc/jam/tls/privkey.pem
admin-tls:                     # optional; admin-API cert. Falls back to tls: if unset
  cert: /etc/jam/tls/admin-fullchain.pem
  key:  /etc/jam/tls/admin-privkey.pem
store-postgres:                  # REQUIRED — the live data (identities, roles, kits, destinations, squawks, session events)
  host: db.internal
  database: jam
  user: jam
  sslmode: verify-full
  password-cred: jam-db
state-dir: /var/lib/jam/state    # optional; relay cursors/markers/receipts (default shown in the key table)
credentials-file: /home/jam/.config/jam/credentials.yml  # optional; the XDG default shown
credentials:                        # name-only DEMANDS — strategies live in the credentials file
  anthropic-key:
  git-pat:
  discord-bot:
  linear-bot:
pool:                               # optional — subscription-OAuth account pool (see below)
  store: /var/lib/jam/pool.json     # host-side pool file (accounts + identity→account bindings)
  cred-name: anthropic-sub          # the anthropic destination cred this pool serves
  refresh-interval: 5m              # optional (default 5m)
  refresh-margin: 15m               # optional (default 15m) — refresh when within this of expiry
operator-auth:                      # see operators.md — omit for loopback-only admin
  oidc:
    issuer:   https://YOUR_TENANT.us.auth0.com/
    audience: https://jam.example.com/admin
    require-scope: jam:admin
    device-client-id: "…"
    device-scope: "openid profile"
runtime:                            # optional — supervisor lease/reconcile timing
  lease-ttl: 60s
  reconcile-interval: 30s           # must be < lease-ttl
  listen: "127.0.0.1:9090"          # OPTIONAL plaintext Attach gRPC dev listener; prod uses the :443 mux
  discord:
    connection: discord-main        # a `jam connection` of kind discord
  requisitioner:
    connection: linear-acme         # a `jam connection` of kind linear or github (the tracker block's)
  wake:                             # optional — wake-on engine timing (see intercom.adoc)
    warm-timeout: 5m
----

The cove-facing `+listen:+`/`+tls:+` endpoint serves *both* the HTTP broker and the
xref:usage/jam/studio-agent.adoc#the-attach-stream[Attach] gRPC stream on the one :443 TLS port: Jam
terminates TLS once, then multiplexes the decrypted stream by `content-type`
(`application/grpc` → the Attach server, everything else → the broker). This is
why a hardened studio — whose sealed egress only permits `+CONNECT … :443+` — can
reach the Attach stream at all. `runtime.listen` is now only an *optional plaintext dev listener* (no TLS, for local testing), not the production path.

|===
|Key |Required |Purpose

|`display-name` |no |Names this Jam in the xref:usage/jam/ui.adoc[admin UI]: the title bar and browser tab title read `<name> Jam`. One line of printable text, at most 64 characters, trimmed; anything else fails serve at startup. Unset, the UI says "Jam". Don't end it in "Jam" — the title bar adds that.
|`operator-notes` |no |The Jam's operator notes (markdown, operators only). Not a serve setting: serve ignores it, a config apply takes it from the followed repo — xref:usage/jam/operator-notes.adoc[].
|`listen` |yes |Address the cove-facing endpoint serves on — *both* the broker and the xref:usage/jam/studio-agent.adoc#the-attach-stream[Attach] gRPC stream, multiplexed by `content-type`. Use `+:443+` in production — a sealed studio can only `CONNECT` to 443.
|`admin-listen` |no |Address the admin API serves on. Omit to run the broker alone.
|`ui-hosts` |no |Extra `Host` values the browser UI accepts on a *loopback* connection, beyond the loopback literals (`127.0.0.1`/`+::1+`/`localhost`). Set a custom name that DNS-binds to loopback (e.g. `jam.local.example`); otherwise the UI refuses it as a possible DNS-rebinding attempt. See xref:usage/jam/ui.adoc#signing-in-one-login-one-principal[Signing in: one login, one Principal].
|`ui-origins` |no |Extra exact origins (`+scheme://host[:port]+`, no path) the browser UI's write checks (`/app/admin` and `/app/user`) accept, besides the request's own `Host`. For a proxy that fronts the admin listener on another address (e.g. `+http://localhost:8090+`). Matching is exact: another port or scheme is another origin. Malformed entries fail serve at startup. They are also the only pages that may frame a preview, and framed preview pages post their status to the first entry, so list the production UI origin first (xref:usage/jam/previews.adoc#framing-the-jam-pane[Framing (the Jam pane)]); serve warns when previews are on and this is empty.
|`dev-identity` |no |*Dev only.* `+{user}+` (a user's name or id; the old `+{project, human}+` still works, with a deprecation warning, as exactly the user that roster human became in the migration): loopback browser requests to `/app` act as that user with *no login*: an admin under the user's first login (or `local` if they have none), and a member through their first OIDC identity, so the user needs one (`jam user oidc`) and a project membership. A real login session still wins. It never applies off loopback, and the `Host` check still runs. serve refuses it unless `admin-listen` is loopback, and logs a `DEV IDENTITY ACTIVE` warning at startup. Never set it in production.
|`tls.cert` / `tls.key` |for a real broker |The broker's own server certificate (it serves its own TLS per connector — no MITM CA).
|`admin-tls.cert` / `admin-tls.key` |no |A separate cert for the admin API; falls back to `+tls:+` when unset.
|`store-postgres` |*yes* |The Postgres store: control plane, squawk Log, session events, allocation ledger. A block of `host`, `port`, `database`, `user`, `sslmode`, and `password-cred`. `serve` refuses to start without it. See xref:usage/jam/serve-store.adoc[].
|`state-dir` |no |Directory for the relay engines' small local files: `relay-cursors.json`, `relay-markers.json`, `relay-receipts.json`. Default `+$XDG_STATE_HOME/jam+`, else ``+~/.local/state/jam+``; created `0700` when a relay needs it. Must resolve to an *absolute* path: with `HOME` unset, a relative `+XDG_STATE_HOME+`, or a relative `state-dir`, `serve` fails at startup rather than write under the working directory. See xref:usage/jam/serve-upgrades.adoc#upgrading-relay-state[Upgrading relay state].
|`session-events-retention` |no |How long session events are kept (`<N>d` or a Go duration; empty keeps forever); see xref:usage/jam/session-events.adoc[].
|`credentials-file` |no |Path to the protected file that supplies the demanded credentials. Default `+${XDG_CONFIG_HOME:-~/.config}/jam/credentials.yml+`. See xref:usage/jam/credentials.adoc[credentials].
|`credentials.<name>` |as needed |The credentials the broker injects, *named only* (an empty entry); strategies live in the credentials file — see xref:usage/jam/credentials.adoc[credentials]. Referenced by a destination's `cred-name`. Values are resolved on the host, in memory — never written to the store. A demanded name the file doesn't supply aborts `serve`.
|`pool` |no |Enables the xref:usage/jam/pool.adoc[subscription-OAuth account pool]: the anthropic destination's credential is resolved from a pool of subscription accounts by cove identity, coves launch in subscription mode, and a background refresher rotates pool tokens. Requires `pool.store` (the path to the pool JSON file) and ``cred-name``; `refresh-interval`/`refresh-margin` default to 5m/15m and `token-url`/`client-id`/`scope` default to the probed Claude Code constants. Absent ⇒ the anthropic destination keeps its configured credential and coves launch in API-key mode.
|`metrics` |no |Serves the operator-attention exposition at `/metrics` on the broker listener: `token-cred` (required) names a demanded credential holding the Prometheus scrape token; `alertmanager-url` (optional) is linked from the admin UI's Health tab. Unset ⇒ no `/metrics`. See xref:usage/jam/monitoring.adoc[].
|`ssh` |no |Enables studio SSH collaboration: Jam's SSH user CA issues short-lived (8h) certs for the studio's `agent` user, and every studio Jam raises trusts it. `ca-cred` (required) names a demanded, plain static credential whose value is the CA's *ed25519* private key (OpenSSH or PKCS#8 PEM, unencrypted), supplied by the xref:usage/jam/credentials.adoc[credentials file] — e.g. generate it with `+ssh-keygen -t ed25519 -f jam-ssh-ca -N ''+` and supply it as `+{ command: ["cat", "/path/to/jam-ssh-ca"] }+`. The key stays in Jam's memory and is never logged. Unset ⇒ SSH collaboration off. Setting it up and using it: xref:usage/jam/collaboration.adoc[collaboration].
|`config` |no |The config repo this Jam follows, the only way its configuration changes: exactly one of `config.github`, `config.gitlab` (each `+{url, cred, branch, dir}+`, an `https` repo) and `config.git` (a local path or SSH: `+{url, branch, dir, cred, host-keys}+`). Unset ⇒ the stored config runs read-only. The fields, URL forms and errors: xref:usage/jam/config-git-sources.adoc[config-git-sources]. A host key.
|`kits` |no |Git credentials for xref:usage/jam/kits-git.adoc[kit git sources]: `kits.git` is a list of `+{url, cred}+`. `url` is a repo-URL *prefix* — `https` (plain `http` only for a loopback host), ending in `/`, with no userinfo, and a *dotted host or loopback* (a single-label host is refused); each url may appear once. `cred` names a demanded, plain static credential (not `+exchange: gcp+`, not the pool's), supplied by the xref:usage/jam/credentials.adoc[credentials file]: the token, or `+user:token+`. Unset ⇒ repos are fetched anonymously (public only). Prefix matching, the username Jam sends and the fetch limits are in xref:usage/jam/kits-git.adoc#credentials-kitsgit[kits-git].
|`blobs` |no |The attachments bucket, S3-compatible (Garage, AWS S3, R2, GCS interop, MinIO): `endpoint` (`+http(s)://host[:port]+`, no userinfo), `bucket`, `region`, `path-style` (true for Garage and MinIO), `max-size` (per file, e.g. `25MB`, the default; at most `1GB`), and `access-key-cred` / `secret-key-cred` — demanded, plain static credentials resolved in memory and never logged. At startup Jam checks the bucket and *refuses to start* if it is unreachable or missing. Unset ⇒ attachments off. See xref:usage/jam/attachments.adoc[attachments].
|`previews` |no |Enables xref:usage/jam/previews.adoc[studio previews], served on the admin listener at `+<name>--<label>.<domain>+`, with login at `jam.<domain>`. `domain` (required) is a lowercase DNS name of at least two labels, e.g. ``jam-previews.example``: use a registrable domain apart from the admin host's, against cookie tossing (framing works either way; serve warns when they share one; xref:usage/jam/previews.adoc#setting-up-previews-operator[Setting up previews (operator)]). `tls.cert` / `tls.key` (required) is a wildcard certificate covering `+*.<domain>+`, served by SNI next to the admin cert. serve fails at startup if it does not cover the domain. Point DNS `+*.<domain>+` at the Jam host. Requires the admin listener on TLS (`admin-listen` plus `admin-tls`, or off-loopback with `+tls:+`) and `operator-auth.oidc.browser-client-id`. Every request for `<domain>` or a name under it goes to the preview handler (404 unless it is a preview or the login host), so reach the admin API and UI at a name outside ``<domain>``: not `jam.<domain>`. serve refuses an `admin-listen` host or `ui-hosts` entry under it. Register `+https://jam.<domain>/__jam/auth/callback+` as a redirect URI with the IdP. Unset ⇒ previews off.
|`destinations` |no |The destinations domain: endpoints with a `subdomain` are reached at `+<subdomain>.<domain>+` on the broker listener. `domain` (required) is a lowercase DNS name of at least two labels; `tls.cert` / `tls.key` (required) is a wildcard certificate covering `+*.<domain>+`. Neither is, holds nor lies under `previews.domain`. See xref:usage/jam/destinations.adoc#destinations-domain[The destinations domain]. Unset ⇒ no endpoint may have a subdomain. A `destinations:` *list* (destination definitions, as serve configs once held them) is ignored with a warning: those live in the config repo.
|`operator-auth.oidc` |to gate the admin API |OIDC operator identity — see xref:usage/jam/operators.adoc[]. Omitted ⇒ the admin API trusts loopback only.
|`runtime.lease-ttl` / `runtime.reconcile-interval` |no |Managed-cove supervisor timing (defaults 60s / 30s; reconcile must be < ttl). See xref:usage/jam/coves.adoc[coves].
|`runtime.listen` |no |Optional *plaintext* Attach gRPC dev listener (no TLS), for local testing. Omit in production — the Attach gRPC is served on the `+:443+` mux alongside the broker.
|`runtime.studio-managers` |no |`true` lets remote Studio Managers connect and registers the `manager` admin verbs. Studios run on Studio Managers only; the old `runtime.launcher` block is removed and refused at startup (see xref:usage/jam/studio-managers.adoc#retiring-the-in-process-launcher[Retiring the in-process launcher]). See xref:usage/jam/studio-managers.adoc[].
|`runtime.requisitioner` |no |Enables the Requisitioner: Jam polls a tracker and raises a managed studio per ready ticket. Requires `role`, `max-concurrent` (>0), exactly one of a `linear` or `github` block, and ``connection``: a *connection* of that kind, whose credential must be demanded in `+credentials:+`. Serve refuses to start on an unknown connection, another kind, or an undemanded credential. The deprecated, Linear-only `+tracker-token-cred: <credential>+` still works (with a warning), but only binds an *existing* `linear` connection whose credential is that one; it never creates or rebinds one. Without one, serve refuses to start (`+… no linear connection (the deprecated *-token-cred no longer creates one; add connections/linear.yml to the config repo, or set runtime.requisitioner.connection)+`, or `+the linear connection's credential is "<x>", not "<y>"+`). Its pre-rename key is still accepted with a warning (xref:usage/jam/renamed-from-harbor.adoc[]). See xref:usage/jam/requisitioner.adoc[].
|`runtime.discord` |no |Enables the resident Discord relay engine (egress and reply-routing ingress). Requires ``connection``: a connection of kind `discord` whose credential (the bot token) is demanded in `+credentials:+`, resolved on the host — never logged/injected; the deprecated `bot-token-cred` only binds an *existing* `discord` connection whose credential is that one, with the same refusals as `tracker-token-cred` above. No Requisitioner needed. Polls every project whose chat service is `discord`. See xref:usage/jam/discord.adoc[discord] and xref:usage/jam/intercom.adoc#enabling-it[intercom].
|`runtime.push` |no |Web Push notifications for the Jam app. `vapid-private-key-cred` (required): a `+credentials:+` entry holding the base64url P-256 VAPID private key, resolved on the host — never on disk, in argv or logs; `subject` (required): `+mailto:+` or `+https:+` contact for the push service; `preview` (default ``true``; `false` sends the body "New message"). |`runtime.wake` |no |Wake-on engine timing: `poll-interval`, `warm-timeout` (`wait-max` is deprecated and ignored: no session is torn down for waiting); and `session-wake-limit`, the agent-to-agent loop breaker (default 8; `0` = session posts never wake sessions; negative refused). Each field falls back to the matching `runtime.requisitioner` field, then the default. See xref:usage/jam/wake-on.adoc[wake-on].
|`runtime.escalation-poll-interval` |no |How often the escalation engine checks waiting sessions (default 30s; falls back to `runtime.requisitioner.escalation-poll-interval`). The engine runs with or without a Requisitioner. See xref:usage/jam/escalation.adoc[escalation].

[#the-broker-model]
== The broker model

The broker is *client-addressed, per-connector* — there is no MITM CA to
install. A studio re-addresses Jam per service (`+ANTHROPIC_BASE_URL=<base>/anthropic+`,
git `insteadOf` → `<base>/git/`), presents only its *identity token*, and Jam:

. authenticates the identity (by token hash) and authorizes the request against
the actor's role scope (see xref:usage/jam/roster.adoc[]),
. swaps the identity token for the *real* downstream credential (from
`+credentials:+`), and
. re-originates the request upstream.

The conscious trade: Jam sees the plaintext of brokered traffic (the client
sent it there on purpose), in exchange for collapsing N cove-side secrets into one
defended Jam.

== Destinations

A destination is one brokered upstream, a file in the config repo; its fields and the destinations domain are in xref:usage/jam/destinations.adoc[].

== The subscription account pool (`+pool:+`)

The optional `+pool:+` block runs cove `claude` as a *pooled subscription
principal* (cheaper, model-entitled) instead of the federated `anthropic-key`
credential: the anthropic destination flips to `bearer`, each cove is seeded a
dummy subscription credential whose access token is its own identity, and the
broker injects a pooled account's real token per request. See
xref:usage/jam/pool.adoc[] for the mechanism, the `jam pool` verb, broker-owned token
refresh, and the egress it needs.

[#exposing-the-admin-api-fail-closed]
== Exposing the admin API (fail-closed)

A loopback `admin-listen` stays plain HTTP. The admin API *refuses to bind
off-loopback unless both* a TLS cert (`admin-tls` or `tls`) *and*
`operator-auth.oidc` are configured — an unauthenticated, plaintext control plane
can never be exposed to the network by accident. To administer a Jam from
another machine, give it a routable `admin-listen`, TLS, and OIDC, then point
clients at its `+https://+` admin URL (xref:usage/jam/operators.adoc[]).

For the broker's threat model and boundary rationale, follow the design-history
pointer in xref:usage/jam/INDEX.adoc[INDEX].
