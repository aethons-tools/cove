= Observing sessions
:summary: The goal for letting a role's agents read other sessions, read-only: the `scope.observe` grant, the brokered `/squawks/observe` endpoints and the `observe_*` tools over session activity and events, what they return, and what they never allow.
:read_when: You are building or reviewing a role that reads other sessions (the optimizer), the `scope.observe` grant, or the `/squawks/observe` endpoints and tools.
:owns: the `scope.observe` role grant, the `/squawks/observe` endpoints and their wire shapes, the `observe_sessions`, `observe_activity`, `observe_streams`, and `observe_events` tools, and their limits. This page is the goal.
Today only operators read other sessions,
in the admin timeline, the NDJSON export, and the session view.
An agent can't.
The optimizer role (process book, *Optimizing the process*) needs to.

[#grant]
== The grant

A role grants its sessions read access to other sessions with `scope.observe` in its file:

[source,yaml]
----
scope:
  observe: all     # every session of every project, live or ended
----

* `all` is the only value.
A role without `scope.observe` gets `403` from every endpoint below.
* It grants reading only.
An observing session can't message, steer, interrupt, or end the sessions it reads,
and its reads aren't visible to them.
* It covers every session: standing, ticket, manual, and personal sessions, with their DMs.
* `jam role` and the admin console's role page show the grant, as for the other scope fields.

[#endpoints]
== Endpoints

Brokered like `/squawks` (xref:usage/jam/intercom.adoc[intercom]):
the studio's identity token, resolved by Jam, never a parameter.
The listing and the events come from the session-event store,
which keeps a session's events after it ends
(xref:usage/jam/session-events.adoc[session-events]);
the store has no session record of its own once Jam tears a session down.

[%header,cols="2,3"]
|===
|Request |Returns

|`+GET /squawks/observe/sessions?since=<RFC 3339>&until=<RFC 3339>+`
|Every session with a stream active in the window (default: the last 24 hours), from the streams' first and last event times (`StreamInfo.FirstAt`, `LastAt`):
`id`; `label`, from the session's intercom party, which outlives it;
`kind`, `project`, `role`, `unit`, `owner`, and `raised_at`, from its events' stamp;
`first_at` and `last_at`, its streams' first and last event times
(a session that ended has no other end time);
`live`, whether Jam still runs it;
and its *lifetime* totals (`sessionevents.Totals`: turns, episodes, tool calls, errors, input and output tokens, cost).
Totals over the window alone are not offered: the totals cover a session's whole life.

|`+GET /squawks/observe/sessions/{id}/activity?anchor=&id=&dir=&limit=+`
|The session's messages in and out, in every conversation,
paged exactly as the session view's activity is (xref:usage/jam/session-activity.adoc[session-activity]):
`anchor` (`end`, `start`, or `id`), `id`, `dir`, and `limit`.

|`+GET /squawks/observe/sessions/{id}/streams+`
|The session's streams, one for each agent process, oldest first:
`stream_id`, `first_at`, `last_at`, `last_seq`, and `events`.

|`+GET /squawks/observe/sessions/{id}/events?stream=&after_seq=&limit=&types=+`
|One stream's captured events, as the export API's fields (xref:usage/jam/session-events.adoc#_export_api[session-events]), with `stream_id`;
`stream` defaults to the newest stream, `after_seq` pages within it,
and `limit` defaults to 500 and is at most 2000.
`types` filters by the event's `type` field (for example `result,assistant`), not its `kind`,
so a reader can take the turn results first
and fetch the full events only for the turns it wants.
Event numbers restart in each stream, so a reader walks the streams from `streams` in order.
|===

`404` for an unknown session or stream; `400` for a bad parameter.
Events keep jam-studio-agent's redaction; nothing more is removed.

[#tools]
== Tools

The studio's messaging server offers `observe_sessions`, `observe_activity`, `observe_streams`, and `observe_events`,
mapping to the preceding endpoints,
only to a session whose role has `scope.observe`
(the session context lists them then, as it does for previews).
