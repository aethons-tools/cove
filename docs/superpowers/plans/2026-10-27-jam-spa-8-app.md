# Jam SPA, slice 8: app-level (Web Push, PWA, service worker) — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the Jam app is a full installable app with notifications, matching the old Inbox:
- **The page's head** carries the PWA manifest link, theme colours and icons (`appui`'s `app-head`). The app registers the `/app/` service worker from its bundle, because the CSP forbids the old inline `<script>`.
- **The principal menu** offers **Notifications: On / Off / Blocked in browser settings**. On iOS outside the Home Screen app it shows **Add Jam to your Home Screen to get notifications**. This ports `uiassets/static/push.js`:
  - subscribe under Jam's VAPID key and store the subscription;
  - Off unsubscribes and deletes it;
  - a live subscription is re-sent once per page session, and one made under a rotated key is replaced;
  - **Sign out** unsubscribes this device first (3 s cap).
- **Focus reporting.** With Web Push on, while a conversation is open in a visible, focused window, the app reports it to `/app/user/push/focus`, so the conversation you're reading isn't pushed. That happens on focus and blur, on a visibility change, and every 30 s; it reports `null` when nothing is open and on pagehide (`layout.html`'s `meFocus`).
- **The app badge** shows the rail's unread total on the installed app's icon and clears at 0 (`meBadge`).
- **The service worker's notification click** reuses an open **app** window when there is one, navigating it to `/app/next/c/<channel>`. Otherwise it keeps today's behavior: an `/app/user/` window, else a new `/app/user/?c=…` window (the default until cutover). It never navigates an `/app/admin/` window.

**Architecture:**
- **Go.**
  - `webapp.Config.Head func(*http.Request) template.HTML` is injected at a new `<!--jam:head-->` marker in `web/app/index.html`.
  - `appui.HeadMeta(r)` renders a new `app-meta` partial, which is `app-head` minus the registration script. `app-head` becomes `app-meta` plus the script, so the old pages are unchanged.
  - `Bootstrap.PushFocus` says whether to report focus.
  - `sw.js` gains area-aware click-through: `jamPickClient` reuses `/app/next/` or `/app/user/`, and `jamTarget(channel, area)`.
- **App.**
  - `src/push/sw.ts` registers the service worker.
  - `src/push/push.ts` is the ported toggle logic over an injectable environment (`navigator`, `Notification`, `fetch`, storage), so it's unit-testable.
  - `PushToggle` is the menu item, and sign-out goes through `signOutDevice`.
  - `useFocusReport(channel)` lives in `ConversationView` and `useAppBadge(unread)` in the rail.

**Tech Stack:** the slice 1–7 stack. No new dependencies.

## Global Constraints

- **Parity:** the old Inbox and admin keep their exact head, `push.js` and service-worker behavior. `TestHeadTemplate`, `TestServiceWorker`, `TestBrowserPushToggle*`, `TestBrowserServiceWorker*` and `TestBrowserInboxRegistersServiceWorker` pass unchanged. Additions are allowed only where this plan says so.
- **The push contract is unchanged:**
  - `POST`/`DELETE /app/user/push/subscriptions` with `PushSubscription.toJSON()` / `{endpoint}`;
  - `POST /app/user/push/focus` with `{channel: id | null}`;
  - the VAPID key, the endpoints, and the service worker's scope `/app/`.
  - Subscriptions made from either UI are the same rows.
- **Shared storage:** `sessionStorage["jam.push.synced:" + userId]` holds the endpoint registered this page session, exactly as `push.js` writes it.
- **Labels, verbatim:**
  - "Notifications: On";
  - "Notifications: Off";
  - "Notifications: Blocked in browser settings";
  - "Add Jam to your Home Screen to get notifications";
  - the failure tooltip "Could not change notifications for this device".
- **CSP:** no inline script. Service-worker registration comes from the bundle, and the head partial injected into the app has no `<script>`.
- **The service worker stays network-only:** no fetch handler, no caches.
- **Size budget:** initial JS ≤ 350 KB gzipped.
- **Docs:** they ship in the same change.
- **gofmt:** use positional struct literals in table tests.

## Review Focus

1. **Shared devices: signing out from the app unsubscribes this device first**, so the next person doesn't get your notifications, and it still signs out within 3 s if the push service hangs. (Task 3 test.)
2. **A subscription made under a rotated VAPID key** is replaced, not re-sent. A subscription already registered this page session isn't re-sent. (Task 3 test.)
3. **Permission denied** shows "Blocked in browser settings", disabled. A browser without Push support shows nothing, except iOS outside the Home Screen. (Task 3 test.)
4. **Focus stops suppressing pushes** when the tab hides, blurs, closes (pagehide sends `null`), or crashes (the server's 60 s expiry is refreshed every 30 s only while focused). (Task 4 test.)
5. **A notification click** goes to the app when an app window is open, and to the old Inbox otherwise. It never navigates an admin window. (Task 2 browser test.)

```js
// jamArea is the Jam area a window shows: 'next' for the Jam app
// (/app/next/), else 'user'.
function jamArea(url) {
  try { return new URL(url).pathname.startsWith('/app/next/') ? 'next' : 'user'; } catch (_) { return 'user'; }
}

// jamTarget is the URL that opens conversation channel in area: the Jam app
// ('next') or the Inbox (the default, until the app replaces it).
function jamTarget(channel, area) {
  if (area === 'next') return channel ? '/app/next/c/' + encodeURIComponent(channel) : '/app/next/';
  return channel ? '/app/user/?c=' + encodeURIComponent(channel) : '/app/user/';
}

// jamPickClient is the index of the window (by URL) a notification click
// should reuse — the first on the Jam app ('/app/next/') or the Inbox
// ('/app/user/') — or -1 to open a new one. An /app/admin/ (or any other)
// window is never navigated away.
function jamPickClient(urls) {
  for (let i = 0; i < urls.length; i++) {
    try {
      const p = new URL(urls[i]).pathname;
      if (p.startsWith('/app/next/') || p.startsWith('/app/user/')) return i;
    } catch (_) { /* not a URL: skip */ }
  }
  return -1;
}
```

```tsx
// PushToggle is the principal menu's per-device Notifications item (the old
// push.js): On subscribes this browser and stores it with Jam; Off removes it.
export function PushToggle({ boot }: { boot: Bootstrap }) {
  const [env] = useState(realEnv);
  const [on, setOn] = useState(false);
  const [busy, setBusy] = useState(supported(env));

    syncOnLoad(env, boot.user.id, boot.pushKey).then((v) => { if (live) setOn(v); }, () => {}).finally(() => { if (live) setBusy(false); });
    return () => { live = false; };

    setFailed(false);
```

**Interfaces:**
- `useFocusReport(channel: string | null, on: boolean)` follows `meFocus`'s rules:
  - while on, it POSTs `{channel}` to `/app/user/push/focus` (raw `fetch`, `keepalive: true`) whenever the *current* value changes. The current value is `channel` when `document.visibilityState === "visible" && document.hasFocus()`, else `null`;

  - every 30 s it re-POSTs a non-null current value (the server forgets it after 60 s);
  - on `pagehide`, if the last POST wasn't `null`, it POSTs `null`;
  - on unmount (another conversation, or leaving), the next mount's check covers the change.

`useFocusReport.ts`:

```ts
import { useEffect, useRef } from "react";

// useFocusReport tells Jam which conversation is open in a visible, focused
// window, so it doesn't push what you're reading (layout.html's meFocus):
// on focus, blur and visibility changes, every 30 s while focused (Jam
// forgets it after 60 s, so a crashed tab stops suppressing), and null on
// pagehide.
export function useFocusReport(channel: string | null, on: boolean) {
  const last = useRef<string | null>(null);
  useEffect(() => {
    if (!on) return;
    const post = (ch: string | null) => {
      last.current = ch;
      void fetch("/app/user/push/focus", { method: "POST", credentials: "same-origin", keepalive: true,
        headers: { "Content-Type": "application/json" }, body: JSON.stringify({ channel: ch }) }).catch(() => {});
    };
    const current = () => (channel && document.visibilityState === "visible" && document.hasFocus() ? channel : null);
    const check = () => { const ch = current(); if (ch !== last.current) post(ch); };
    const hide = () => { if (last.current) post(null); };
    window.addEventListener("focus", check);
    window.addEventListener("blur", check);
    document.addEventListener("visibilitychange", check);
    window.addEventListener("pagehide", hide);
    const tick = setInterval(() => { const ch = current(); if (ch) post(ch); else check(); }, 30_000);
    check();
    return () => {
      window.removeEventListener("focus", check);
      window.removeEventListener("blur", check);
      document.removeEventListener("visibilitychange", check);
      window.removeEventListener("pagehide", hide);
      clearInterval(tick);
    };
  }, [channel, on]);
}
```

A note on the test: in the expected sequence, re-focusing on `chn_a` posts "chn_a", because `last` was `null`. Then the rerender to `chn_b` posts "chn_b". Writing `last.current` inside an effect is allowed by the lint rule.

```ts
import { useEffect, useRef } from "react";

// useAppBadge shows n (the rail's unread total) on the installed app's icon
// and clears it at 0 (layout.html's meBadge); unsupported browsers ignore it.
export function useAppBadge(n: number | undefined) {
  const shown = useRef<number | undefined>(undefined);
  useEffect(() => {
    if (n === undefined || n === shown.current) return;
    shown.current = n;
    const nav = navigator as Navigator & { setAppBadge?: (n: number) => Promise<void>; clearAppBadge?: () => Promise<void> };
    try {
      if (n > 0) nav.setAppBadge?.(n).catch(() => {});
      else nav.clearAppBadge?.().catch(() => {});
    } catch { /* unsupported */ }
  }, [n]);
}
```
