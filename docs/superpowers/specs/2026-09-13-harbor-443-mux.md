# harbor: multiplex Attach gRPC onto the cove-facing :443 TLS listener (COV-157)

**Status:** design approved, pre-plan
**Issue:** COV-157 (slice 5 of the cove-management tree — the transport prerequisite for a real Launcher)
**Foundation:** COV-153 (Attach gRPC server), COV-155 (cove-master client). **Design history:** `docs/superpowers/specs/2026-09-10-harbor-design.md`; `docs/superpowers/specs/2026-09-13-harbor-attach-stream.md`.

## Summary

A hardened cove's sealed egress permits outbound **only on :443** — enforced at two layers baked into the hardening image and not kit-overridable:

- nftables (`…/hardening/image-files/etc/nftables.conf`): only the squid user may egress, only on `tcp dport {80,443}`.
- squid (`…/etc/squid/squid.conf`): `acl SSL_ports port 443` + `http_access deny CONNECT !SSL_ports`.

So the COV-153 plaintext `runtime.listen` on a separate port is unreachable from a real cove (even host-gateway traffic to the host goes through squid and is 443-only). This slice **multiplexes the Attach gRPC onto harbor's existing cove-facing :443 TLS listener** (the broker's listener) and switches `cove-master` to a **TLS dial that rides the squid CONNECT proxy**. After this, a hardened managed cove can actually reach the Attach stream — unblocking the real Launcher (next slice).

This is a **transport-only** slice: no Launcher, no image changes.

## Harbor side — the :443 demux

Today `cmd/at-harbor serve` serves the broker via `http.Server{Addr: cfg.Listen, Handler: broker}.ListenAndServeTLS(cfg.TLS.Cert, cfg.TLS.Key)` (harbor terminates its own TLS; Go's default ALPN advertises `h2,http/1.1`, so the broker also speaks h2). The Attach gRPC is a *separate* plaintext `grpc.Server.Serve` on `runtime.listen`.

**Change:** serve both on the one 443 TLS listener, demuxed by `content-type: application/grpc` (not ALPN — the broker negotiates h2 too, so ALPN can't distinguish them):

1. Terminate TLS once: `tlsLis := tls.NewListener(rawLis, &tls.Config{Certificates: []tls.Certificate{cert}, NextProtos: []string{"h2","http/1.1"}})` where `cert = tls.LoadX509KeyPair(cfg.TLS.Cert, cfg.TLS.Key)` and `rawLis = net.Listen("tcp", cfg.Listen)`.
2. `m := cmux.New(tlsLis)`. The matchers peek the decrypted stream:
   - `grpcL := m.MatchWithWriters(cmux.HTTP2MatchHeaderFieldSendSettings("content-type", "application/grpc"))` — the documented cmux↔gRPC recipe (the server must be able to send HTTP/2 SETTINGS first).
   - `httpL := m.Match(cmux.Any())` — everything else → the broker.
3. `go gs.Serve(grpcL)` (the real `grpc.Server.Serve(net.Listener)`; **insecure** server creds because TLS is already terminated at `tlsLis`), `go (&http.Server{Handler: broker}).Serve(httpL)` (plain `Serve`, conns already decrypted), and `m.Serve()` blocks (replacing the old blocking `ListenAndServeTLS`).

The `attach.Server` + `sup.SetControlSink(rsrv)` wiring is unchanged; the `grpc.Server` is now built unconditionally (it serves 443) and the attach server's in-metadata auth (identity token + launch secret) is unaffected.

`runtime.listen` is **kept as an optional plaintext dev listener** on the *same* `grpc.Server` (`go gs.Serve(plaintextLis)`), so local/hermetic dev without TLS still works. One `attach.Server`, one `grpc.Server`, one ControlSink, served on one or two listeners.

**New dependency:** `github.com/soheilhy/cmux v0.1.5` (fetch verified through the locked egress with `GOPROXY=https://proxy.golang.org GOSUMDB=off`). Chosen over grpc-go's experimental `Server.ServeHTTP` because the Attach RPC is a long-lived bidi stream and we want the full-featured `grpc.Server.Serve(net.Listener)` path.

### Testable seam

Extract the mux wiring into a helper so it can be exercised on a real loopback listener:

```go
// serveMux terminates TLS on lis and splits gRPC (content-type application/grpc)
// to gs from everything else to httpHandler, serving all three until lis closes.
func serveMux(lis net.Listener, tlsCfg *tls.Config, gs *grpc.Server, httpHandler http.Handler) error
```

`cmdServe` builds `tlsCfg` (cert + NextProtos) and calls `serveMux(rawLis, tlsCfg, gs, broker)`.

## Cove side — cove-master TLS dial

`internal/covemaster/client.go` already dials `grpc.NewClient("passthrough:///"+Addr, opts...)` with **no custom `WithContextDialer`** in production, so grpc-go's built-in dialer is in play — and it honors `HTTPS_PROXY`. The cove's sealed env sets `https_proxy=http://127.0.0.1:3128` (squid), and `harbor.host` is not in `NO_PROXY` (`localhost,127.0.0.1,::1,.internal`), so grpc will CONNECT harbor:443 through squid, then TLS-handshake (ALPN h2) over the tunnel. No client library change is needed — the client is transport-agnostic; only the injected creds change.

**Change (`cmd/cove-master/main.go`):** the production dial options swap `insecure.NewCredentials()` → `credentials.NewTLS(&tls.Config{})` (empty config → grpc fills `ServerName` from the dial target authority, validates against the **system trust store**). `AT_HARBOR_RUNTIME_ADDR` is now expected to be `harbor.host:443`. Expose the creds via a tiny helper so it's assertable:

```go
func clientTransportCreds() credentials.TransportCredentials { return credentials.NewTLS(&tls.Config{}) }
```

Tests keep injecting the bufconn dialer + insecure creds via `covemaster.Config.DialOptions` — unchanged.

### Trust

Reuse the **system trust store**. The broker is already reached at `https://harbor.host` and validated by system roots (there is zero client-side CA config in the tree today); the Attach gRPC reuses the same host + cert, validated the same way. A private-CA deployment would need CA distribution for the broker too — that's a separate, out-of-scope concern.

## Tests (hermetic)

- **harbor demux** (`cmd/at-harbor`, loopback, no external egress): generate an in-test self-signed cert (crypto/x509 + ed25519/RSA), stand up `serveMux` on a `127.0.0.1:0` listener with a trivial `grpc.Server` (the attach service or a tiny test service) and a trivial broker `http.Handler`. Then (a) dial it with a gRPC client over TLS (RootCAs = the in-test CA) and assert the RPC reaches the gRPC server; (b) issue an HTTPS request and assert it reaches the broker handler. Proves both protocols route correctly on one port.
- **cove-master creds** (`cmd/cove-master`): assert `clientTransportCreds().Info().SecurityProtocol == "tls"` (and, as a guard, that it is not `"insecure"`). Keep `TestBuildConfigRequiresEnv`.
