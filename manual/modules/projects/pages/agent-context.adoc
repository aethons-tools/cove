= Telling a project's agents what they need to know
:page-area: projects
:page-id: projects/agent-context
:page-conventions: sentence-case, quiet-grid, collapsible-rows, add-at-bottom, thermometers, view-then-edit, field-errors, rendered-markdown

Every agent raised in a project starts with the project's *agent context*:
core instructions it always sees,
progressive instructions it opens only when relevant,
and a list of the project's resources.
You see and edit it on the project page,
in the *Agent context* card,
under *Config › Projects › _your project_*.

image::agent-context-goal-view.png[The Agent context card, viewing,800]

TIP: Try it: link:{attachmentsdir}/agent-context-prototype.html[open the clickable prototype^].
Nothing in it is saved.

Changes reach each agent the next time it is raised.
Never put a credential in agent context;
every agent can read it.

== Viewing and editing

The card always has the same layout.
Normally it is read-only:
markdown shows formatted,
you can expand progressive instructions to read them,
and every thermometer shows where you stand.
Click *Edit* to make the whole card editable;
*Cancel* drops your changes,
*Save context* keeps them.

image::agent-context-goal-edit.png[The Agent context card, editing,800]

== Core instructions

*Core instructions* hold what every agent must always know:
the project's goal and its standing rules.
The thermometer below shows how much of the 1,200-byte budget you have used.
When the project has resources,
the budget includes the one line that points agents at them.

== Progressive instructions

A *progressive instruction* is detail an agent reads only when its *Read when* matches the task at hand,
such as how to cut a release.

* Each instruction is a row showing its name, *Read when* and size.
Click *▸* to expand it and *▾* to collapse it.
* To add one, click *+ new instruction…* at the bottom of the list;
it opens expanded.
* An instruction has a name ending in `.md`,
a *Read when*,
and a markdown body.
The thermometer under *Read when* shows its 160-byte limit.
* The thermometer below the list shows all progressive instructions together against their 64 KiB.
A project can have up to 20.

== Resources

Resources are the repos, docs, trackers and links the project's agents should know about.
The grid looks like a plain table:
click a cell to edit it,
press Tab or Enter to move on,
and Esc to leave the cell.
To add one, click *+ new resource…* at the bottom of the grid.
Each resource needs a unique name, a kind (repo, doc, tracker or url) and a ref;
the note is optional.
A project can list up to 50.

== Saving

A problem shows on the field that has it,
the footer counts them,
and *Save context* stays off until there are none.
Saving replaces the project's whole agent context at once.

*View as YAML* shows the same context in the `jam context` file format,
for copying into a config repo.
*Clear context* removes it entirely.
