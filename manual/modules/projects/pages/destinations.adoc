= Reaching outside services through destinations
:page-area: projects
:page-id: projects/destinations
:page-conventions: sentence-case, quiet-grid, collapsible-rows, add-at-bottom, thermometers, view-then-edit, field-errors

A *destination* is an outside service,
such as GitHub or Linear,
that agents reach through Jam
without ever holding its credential.
Jam keeps the credential,
checks each agent's own identity,
and adds the real credential on the way out.

One service often needs several addresses.
GitHub has git, its REST API and GraphQL;
Linear has its API and its MCP server.
A destination holds all of them as *endpoints*
that share one credential and one agent connector,
so you set those up once.

You see and edit a destination on its page,
under *Config › Destinations › _name_*,
on a branch of the config repo.

image::destinations-view.png[The github destination, viewing,800]

== Viewing and editing

The *Destination* card always has the same layout.
Normally it is read-only.
Click *Edit* to make the whole card editable;
*Cancel* drops your changes,
*Save destination* keeps them.

image::destinations-edit.png[The github destination, editing,800]

The card shows the destination's *Credential*,
the name of the secret Jam applies upstream,
and an optional *Note*.

== Endpoints

Each endpoint is a row in the *Endpoints* grid:

Name::
Unique in this destination.
The agent connector uses it to point at the endpoint.
Subdomain::
The endpoint is reached at `<subdomain>.<jam host>`.
Leave it empty to stay on the Jam host itself.
Route::
The path the endpoint answers on, such as `/api/v3/`.
Leave it empty to take every path on the endpoint's host.
Upstream::
The service's address that requests go on to.
Identity in::
Where the agent presents its Jam identity.
Apply as::
How Jam sends the real credential upstream.
Allowed paths::
Optional; only these upstream paths are let through.
Route git::
Whether agents' git for the upstream's host goes through this endpoint.

The grid looks like a plain table:
click a cell to edit it,
press Tab or Enter to move on,
and Esc to leave the cell.
To add an endpoint, click *+ new endpoint…* at the bottom of the grid.
A destination can have up to 10;
the thermometer below the grid shows how many it has.

=== Addresses

An endpoint needs a subdomain, a route or both.
No two endpoints in the whole Jam may have the same subdomain and route.

A request matches the most specific endpoint.
The route is taken off before the request goes upstream;
with no route, the path goes on unchanged.
For example, with the Jam at `jam.example.com`:

* `git.jam.example.com/aethons-tools/cove.git` goes to `https://github.com/aethons-tools/cove.git`.
* `gh.jam.example.com/api/v3/repos/x` goes to `https://api.github.com/repos/x`.
* `gh.jam.example.com/other` matches no endpoint and is refused.
* An endpoint with subdomain `linear` and no route sends `linear.jam.example.com/graphql` to `https://api.linear.app/graphql`.

A subdomain lets a client that only takes a host,
such as `gh`,
reach a service without needing a path of its own.
Two GitHub destinations on two subdomains do not get in each other's way.

Subdomains work once the Jam has a domain for them,
as it has for previews.
Until then,
a subdomain shows an error at its cell.

=== Identity and credential

*Identity in* and *Apply as* each offer four presets
(`bearer`, `basic-password`, `x-api-key`, `raw`)
and *expression*.

Click *▸* on a row to expand it and *▾* to collapse it.
Expanded, the row shows what its choices mean.
For a preset these fields are read-only.
For *expression* you edit them:

* *Identity in*: the header the identity arrives in,
the prefixes to cut from it,
and its encoding (`raw` or `basic`).
* *Apply as*: the header to set,
a template with `+{cred}+` exactly once,
its encoding,
and, for `basic`, the user to send.

=== Header logging

Also in the expanded row,
*Log incoming headers* (`none`, `examined`, `all`)
and *Log outgoing headers* (`none`, `changed`, `all`)
turn on header logs for that endpoint alone,
for debugging.
Credentials are never logged in clear.
An endpoint that logs shows a *logging* tag in its row,
so one left on is easy to spot.

== Agent connector

The *Agent connector* lists the environment variables agents set to use the destination.
It is set once for the whole destination.
A value can use these placeholders:

* `+{host:<endpoint>}+`: the endpoint's host, such as `gh.jam.example.com`.
* `+{url:<endpoint>}+`: the endpoint's host and route, such as `https://gh.jam.example.com/api/v3`.
* `+{token}+`: the agent's Jam identity.

For example, `gh` needs `GH_HOST` set to `+{host:rest}+`;
it adds `/api/v3/` and `/api/graphql` itself.

== Roles

A role lists the destinations it may use.
It gets every endpoint of each one.
When a role should reach only part of a service,
make that part a destination of its own.

== Saving

A problem shows on the field that has it:
a missing or repeated name,
an endpoint with neither subdomain nor route,
a subdomain and route another endpoint has,
or a template without `+{cred}+`.
The footer counts problems,
and *Save destination* stays off until there are none.
Saving is a commit to the config branch.

Destinations defined before endpoints existed keep working unchanged.
Each is a destination with one endpoint,
named after the destination,
on its route.
