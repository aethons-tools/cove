= Destinations
:page-area: ROOT
:page-id: ROOT/concepts/destination
:page-conventions: sentence-case

A *destination* is an outside service,
such as GitHub or Linear,
that agents reach through Jam
without ever holding its credential.
Jam keeps the credential,
checks each agent's own identity,
and adds the real credential on the way out.

== Endpoints

One service often needs several addresses.
GitHub has git, its REST API and GraphQL;
Linear has its API and its MCP server.
A destination holds all of them as *endpoints*
that share one default credential and one agent connector,
so you set those up once.

Each endpoint has a name,
unique in its destination,
an address on Jam,
and the service's address that requests go on to.
A destination has up to 10 endpoints.

For now you list a destination's endpoints in its file in the config repo.
The destination's page shows and edits its first endpoint
and keeps the others as they are.

== Addresses

An endpoint is reached at `<jam host><route>`,
or, when the Jam has a domain for subdomains,
at `<subdomain>.<domain><route>`.
The subdomain and the route are each optional,
but an endpoint has at least one of them.
No two endpoints in the whole Jam have the same subdomain and route,
and no route on the Jam host may take a path Jam itself uses,
such as `/connector` or `/squawks`.

A request goes to the most specific endpoint that matches it.
The route is taken off before the request goes on;
an endpoint with no route takes every path on its subdomain,
and the path goes on unchanged.
For example, with the Jam at `jam.example.com`,
its subdomains under `jam.example.com` too,
and a GitHub destination with endpoints on `/api/v3/` and `/api/`:

* `jam.example.com/api/v3/repos/x` goes to the `/api/v3/` endpoint, as `/repos/x`.
* `jam.example.com/api/graphql` goes to the `/api/` endpoint, as `/graphql`.
* `jam.example.com/other` matches no endpoint and is refused.
* An endpoint with subdomain `linear` and no route sends `linear.jam.example.com/graphql` to `https://api.linear.app/graphql`.
* `other.jam.example.com/graphql` matches no endpoint and is refused.

A subdomain lets a client that only takes a host
reach a service without a path of its own.
On a subdomain, only that subdomain's endpoints answer;
Jam's own paths are not there.
Subdomains work once the Jam has a domain for them,
as it has for previews;
without one, an endpoint with a subdomain is refused.

== Identity and credential

An agent presents its own Jam identity,
never the service's credential.
For each endpoint,
*Identity in* says where Jam finds that identity in the request,
and *Apply as* says how Jam sends the real credential upstream.
Common services fit a preset;
any other can be described by a custom header spec.
Each endpoint can also limit the paths it lets through,
and log its headers for debugging.

== The agent connector

A destination tells agents how to use it:
the environment variables they set,
such as `GH_HOST` for `gh`,
and whether their git goes through it.
They are set once for the whole destination.
Every agent that may use the destination gets these at its next start.

A value can use these placeholders:

* `+{host:<endpoint>}+`: the endpoint's host, such as `gh.jam.example.com`,
or the Jam host when the endpoint has no subdomain.
* `+{url:<endpoint>}+`: the endpoint's host and route, such as `https://gh.jam.example.com/api/v3`.
* `+{token}+`: the agent's Jam identity.

A placeholder must name an endpoint of the destination.
For example, `gh` needs `GH_HOST` set to the host of an endpoint on its own subdomain;
it adds `/api/v3/` and `/api/graphql` itself.

An endpoint that routes git sends the agents' git for its service's host
through the endpoint's address,
on its subdomain when it has one.
Two destinations an agent may use must not set one variable differently,
or route git through two addresses;
when they do, Jam reports a conflict instead of picking one.

== Roles

A role lists the destinations its agents may use,
and gets every endpoint of each one.
Each destination has a default credential;
a role can use another credential for it instead,
and that credential then applies to all of the destination's endpoints.
When a role should reach only part of a service,
that part is a destination of its own.

Destinations defined before endpoints existed keep working unchanged:
each is a destination with one endpoint on its route.
